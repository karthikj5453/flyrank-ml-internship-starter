▲ FlyRank ML Internship — Search Intelligence Capstone

Beating the Rule: A Client-Holdout Model for Content Decline Review

Which pages should a content editor review first, out of thousands? This paper builds a binary decline classifier on 30,000 anonymized FlyRank content pages across 32 clients, validates it on a client-holdout split so the model is never tested on a client it trained on, and compares it against a transparent hand-written baseline rule. The best model (random forest) reaches precision@50 of 0.74 against the baseline's 0.24 — roughly a 3× lift — and produces a ranked, reason-coded review queue over all 30,000 pages.

Author: Karthik Jadhav Lane: Refresh / Content Opportunity Scoring Data: FlyRank ML Internship starter dataset (30,000 rows, 32 clients)
01 — Introduction

What decision this supports

FlyRank's content system already flags pages with hand-written rules — a health score, quick-win tags, needs-attention flags. These rules run in production and work, but they run out where signals get numerous and tangled. This capstone asks a narrow, practical question: on the same data, can a trained model outrank the hand rule at picking which pages an editor should look at first? The output is a ranked review queue with plain- language reason codes — decision support for a human, not an autonomous publishing system.

02 — Data

Release, windows, exclusions

Data is the FlyRank ML Internship starter release: content_refresh_anonymized.csv — 30,000 rows, one per pseudonymized content item, spanning 32 pseudonymized clients. All metrics are trailing-90-day totals, with a 30-day-vs-prior-30-day comparison built in for the trend signal.

  • No rows were dropped. Missingness (concentrated by content_type — e.g. one content type ships with no keyword data at all) was handled by explicit imputation flags and category filling, not row deletion, since dropping rows would have silently removed entire content types.
  • No client names, domains, URLs, titles, or keywords appear in the dataset or this paper — content_id and client_id are pseudonyms used only for grouping and splitting.
Final scored set: all 30,000 pages. Declining-label rate: 54.2% (16,262 pages) — this is the number every metric below has to beat.
03 — Methodology

Label, features, baseline, validation, leakage checks

Label — is_declining_label = 1 when 30-day impressions fell more than 20% versus the prior 30 days (trend_direction == "down").

Features — 17 numeric signals (impressions, clicks, CTR, position, content age, freshness, word/char count, keyword competition) + 8 categorical signals (content type, intent, age/freshness/word-count/impression/position tiers). Excluded by design: trend_direction and trend_pct (the label's own source columns — including them would let the model read the answer), and provider_used / model_used (generation metadata, not a search signal).

Baseline — a transparent hand-written rule (stale × visible × trouble-signal, no fitted weights) — readable in one sentence, scored the same way the model is scored.

Models — logistic regression, decision tree, random forest, compared on the identical split and metric set.

Validation — client-holdout split: held-out clients never appear in training. This is the honest choice here over a random row split, because rows from the same client share hidden structure (a client's site, content style, or SEO maturity) — a random split would let a model partly memorize the client rather than learn the general pattern.

Leakage self-check (run live in the notebook): confirmed the label's source columns and all ID columns are absent from every model's feature list — zero overlap.

05 — Limitations & honest framing

What this is not

  • The label is a rule about 30-day impression change, not an editorial judgment that a page needs work — declines can come from seasonality or a client's own site change, not content quality.
  • This is a single 90-day snapshot. No refresh was actually observed, so nothing here is a claim about what happens after a page is edited — it's decision support, not a causal claim.
  • Precision@50 of 0.74 means roughly 13 of the top 50 flagged pages are still likely false positives. The queue is a starting point for human review, not autopilot.
  • Client-holdout validation is honest for generalizing to new clients within this same portfolio — it says nothing about clients or verticals outside this dataset.
